# Audio local para KDS y mesero

Fecha: 2026-10-13. Alcance: selección de herramienta; este documento no acredita reproducción en una terminal.

## Decisión

**Inferencia para Umi:** usar `audioplayers: 6.8.1`, con versión exacta y archivos WAV locales en el APK.
La API del paquete cubre avisos breves. El proveedor recomienda `AssetSource` para archivos del proyecto.
No se necesita un canal nativo propio para reproducir estos archivos.
[Fuente primaria: API de AssetSource](https://pub.dev/documentation/audioplayers/6.8.1/audioplayers/AssetSource-class.html).

**Hecho documentado:** la versión 6.8.1 se publicó el 2026-06-27.
Requiere Dart `^3.6.0` y Flutter `>=3.44.0`. Usa una licencia MIT.
El historial incluye correcciones de preparación y compatibilidad de Kotlin.
[Metadatos oficiales](https://pub.dev/api/packages/audioplayers),
[licencia](https://pub.dev/packages/audioplayers/license),
[historial](https://pub.dev/packages/audioplayers/changelog).

**Hecho local:** `apps/umi-pos/pubspec.yaml` exige Dart `>=3.12.0 <4.0.0` y Flutter `>=3.44.0`.
Antes de esta selección no declaró una dependencia de audio.

**Hecho documentado:** `just_audio` 0.10.6 se publicó el 2026-06-29 y requiere Flutter `>=3.27.0`.
Su licencia es MIT. Android usa ExoPlayer. Linux requiere otro paquete de implementación.

[documentación del proveedor](https://pub.dev/packages/just_audio),
[licencia](https://pub.dev/packages/just_audio/license).

**Compromiso respaldado por fuentes:** ambos reproductores cubren assets Android.
`audioplayers` documenta un modo para efectos breves. `just_audio` concentra más funciones en reproducción de medios.
Esto justifica la selección por alcance, sin afirmar una diferencia de tamaño o latencia no medida.

[just_audio](https://pub.dev/packages/just_audio).

[Android ToneGenerator](https://developer.android.com/reference/android/media/ToneGenerator),
[canales de Flutter](https://docs.flutter.dev/platform-integration/platform-channels).

Declara implementaciones Android e iOS. La ficha ofrece sonidos del sistema y reproducción de archivos.

## Adopción y degradación

**Inferencia para Umi:** el coste es una dependencia Dart, los paquetes de plataforma resueltos y tres assets.
El paquete principal declara implementaciones para seis plataformas.
Linux compila su plugin aunque la aplicación decida mantener silencio; confirmar sus requisitos durante la verificación.
[Metadatos oficiales](https://pub.dev/api/packages/audioplayers).

**Inferencia para Umi:** crear el reproductor sólo si `!kIsWeb && defaultTargetPlatform == TargetPlatform.android`.
En Linux y web usar una implementación silenciosa del mismo servicio.
Capturar fallos de preparación o reproducción para conservar el funcionamiento de la pantalla.
La degradación es una política de Umi; el paquete no la aplica automáticamente.

**Inferencia para Umi:** usar un archivo distinto por evento: ticket nuevo, vencimiento e ítem listo.
Declarar los archivos en `flutter.assets`. Usar `AssetSource`, sin URL ni descarga.
Elegir WAV PCM breve; verificar el archivo real en Android antes de afirmar compatibilidad.

**Hecho documentado:** `ReleaseMode.release` libera los recursos al terminar; `ReleaseMode.loop` repite el archivo.
`PlayerMode.lowLatency` no emite eventos de finalización y obliga al cliente a detener el reproductor.
[ReleaseMode](https://pub.dev/documentation/audioplayers/6.8.1/audioplayers/ReleaseMode.html),
[PlayerMode](https://pub.dev/documentation/audioplayers/6.8.1/audioplayers/PlayerMode.html).

**Inferencia para Umi:** iniciar con `PlayerMode.mediaPlayer` y `ReleaseMode.release` para avisos esporádicos y finitos.
Usar `stop()` al silenciar y `dispose()` al cerrar el propietario del servicio.
Cambiar a `lowLatency` sólo si una medición Android demuestra una demora relevante.

**Inferencia para Umi:** la decisión de sonar debe vivir fuera del reproductor.
El primer snapshot arma la referencia y guarda silencio. Los diffs posteriores detectan los tres eventos.
El vencimiento debe sonar una vez por ticket y estación, con un conjunto de identificadores ya avisados.
Un temporizador compara el reloj con el umbral; no necesita modificar el transporte realtime existente.
El aviso al mesero necesita limitarse a cuentas de su sesión, sin exigir permiso de cocina.
La implementación de esa lectura y sus permisos pertenece al frente funcional, no a esta selección.

## Método y límites

Herramientas de investigación: documentación oficial, Pub API y código del proveedor.
Se usaron los peldaños 1, 2 y 3 de la doctrina del repositorio.
Formato: Prettier 3.9.4 mediante `npx prettier --write`.
Fuente del método: `.agents/skills/research/SKILL.md` y `docs/agents/tool-and-research-doctrine.md`.

La página de ToneGenerator falló dos veces con el lector web.
La ruta alternativa, `urllib.request` contra la misma URL oficial, devolvió HTTP 200 y el contenido de la referencia.
Pub API permitió comprobar versiones exactas, fechas y restricciones sin depender del texto indexado.

**NO VERIFICADO:** volumen audible, latencia, mezcla de tres eventos, tamaño incremental del APK y comportamiento de silencio del iMin.
**NO VERIFICADO:** ejecución de los assets con la red apagada y reproducción en A9/A11.
**NO VERIFICADO:** avisos con la app en segundo plano; esta decisión cubre el POS activo y no promete notificaciones push.
Estas comprobaciones requieren el único build final y las terminales reales.

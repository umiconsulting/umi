# Store screenshot index — inventory-capable POS and inventory apps

- Captured: 2026-09-18 (local, America/Mazatlan).
- Images: 238. Phone: 132. iPad: 106. Every file is a real product
  screenshot from the vendor's own App Store listing.
- Total size: 46 MB. Each file is downscaled to a maximum edge of 1200 pixels.
  The source URL in each row returns the full-size original.
- Tool: `curl` 8.5.0 with a desktop browser User-Agent, against Apple's public
  search and lookup APIs:
  `https://itunes.apple.com/search?term=<name>&entity=software&country=us`
  and `https://itunes.apple.com/lookup?id=<appid>&country=us`.
- The lookup JSON holds `screenshotUrls` (phone) and `ipadScreenshotUrls`
  (iPad). Both arrays gave direct image URLs.
- Size upgrade: the feed returns a small thumbnail URL. The same asset is
  available at a larger size when the last path segment changes to
  `2000x2000bb.<ext>`. Every file here used that route. All 238 image fetches
  returned HTTP 200. All 20 lookup calls returned HTTP 200.
- Read method: a contact sheet of six images per app, then a full-size read of
  every screen that the classification matters for. The description column is
  read from the image. It is not a guess from the file name.

## Class values

| Class                   | Meaning                                                                                                     |
| ----------------------- | ----------------------------------------------------------------------------------------------------------- |
| `INVENTORY`             | A bare product screenshot of a stock screen: stock list, count sheet, stock level, waste, or purchase order |
| `SALES`                 | A bare sale, order, ticket, or payment screen                                                               |
| `DASHBOARD`             | A bare report, sales summary, or analytics screen                                                           |
| `OTHER`                 | A bare schedule, chat, team, or settings screen                                                             |
| `MARKETING + INVENTORY` | The vendor draws a headline or a device frame over an inventory screen                                      |
| `MARKETING + SALES`     | A marketing composite over a sale screen                                                                    |
| `MARKETING + DASHBOARD` | A marketing composite over a report screen                                                                  |
| `MARKETING + OTHER`     | A marketing composite over a schedule, chat, team, or settings screen                                       |

Read the class in two parts. `MARKETING +` means the vendor drew a caption or a
device frame over a real screen. The word after the plus names the screen
inside. The tail after the dash names the exact screen.

An app store listing is a marketing surface. 77 of the 238 shots carry a drawn
caption. Count an image as inventory evidence when the class is `INVENTORY` or
`MARKETING + INVENTORY`. That is 76 images across 15 apps.

```sh
curl -s "https://itunes.apple.com/search?term=marketman&entity=software&country=us&limit=5" | jq -r '.results[].trackId'

```

the source URL. Do not rehost them in a product or a marketing page.

## Why the images in this folder are not in git

The screenshots are NOT committed. This index is the evidence: it holds the source
URL, the app id, the device class, and what each screen shows, so every image is
reproducible with the route recorded below.

The reason is size. The five harvest folders hold 193 images and 53 MB, against a
repository that already tracks 2.4 MB of research images and a 91 MB `.git`. The
`.gitignore` entry that keeps them out is documented in the repository root.

The curated evidence the reports cite IS committed: the eight official Lightspeed
screenshots at the root of this folder, and the before and after screen sets under
`docs/research/2026-09-18-design-taste/assets/screens/`.

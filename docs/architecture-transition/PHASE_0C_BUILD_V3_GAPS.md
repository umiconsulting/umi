# Phase 0C — Build-v3 Gap Register

The complete gap records are in
[`phase-0c-build-v3-gaps.json`](./phase-0c-build-v3-gaps.json).

## P0 — Entry blockers

1. Establish one Supabase migration authority.
2. Prove the deployed RLS role and branch context.
3. Remove direct Supabase client authority.
4. Complete the neutral contract artifact.
5. Record one green entry certification.

## P1 — First sale blockers

1. Complete durable identity sessions, branch grants, and POS permissions.
2. Add POS device proof, operator PIN, and command-bound approval.
3. Complete the POS catalog, price, tax, media, and availability contract.
4. Add atomic checkout, payments, receipts, and refunds.
5. Add inventory and physical-cash ledgers.
6. Add POS audit, redaction, correlation, and distributed abuse controls.

## P2 — Pilot blockers

1. Consolidate customer and loyalty authority.
2. Complete KDS projection and bounded event delivery.
3. Add encrypted offline replay and reconciliation.
4. Prove staging, backup, restore, deployment, and rollback.
5. Activate provider DDoS controls, WAF, backpressure, and queue limits.

## P3 — Production hardening

- Add reconciled, security-invoker POS reporting.
- Add SLOs, alerts, retention, and incident drills.

## P4 — Deferred capabilities

- Add POS Assistant tools after safe read models exist.
- Add integrated acquiring after the pilot.
- Replace Swift KDS after provider certification.
